# Memory 🧠

Production-ready cross-platform mobile application and backend for personal memory capture and retrieval.

---

## 🚀 Independent Getting Started

Both applications can be run independently or via the monorepo root scripts.

### 1. Server Setup (`server/`)

1. Change directory to `server`:
   ```bash
   cd server
   ```

2. Setup environment variables:
   ```bash
   cp .env.example .env
   ```
   *(Configure MySQL connection details and a 32+ character `BETTER_AUTH_SECRET`)*

3. Install dependencies:
   ```bash
   npm install
   ```

4. Build or check types:
   ```bash
   npm run typecheck
   npm run build
   ```

5. Start the development server:
   ```bash
   npm run dev
   ```
   - Server runs on `http://localhost:4000`
   - Health check: `http://localhost:4000/health`

---

### 2. Mobile App Setup (`mobile/`)

1. Change directory to `mobile`:
   ```bash
   cd mobile
   ```

2. Setup environment variables:
   ```bash
   cp .env.example .env
   ```
   *(Defaults to `http://10.0.2.2:4000` for Android Emulator, `http://localhost:4000` for iOS)*

3. Install dependencies:
   ```bash
   npm install
   ```

4. Check types:
   ```bash
   npm run typecheck
   ```

5. Start the Metro development server:
   ```bash
   npm start
   ```

6. Run on devices / emulators:
   - **Android**: `npm run android`
   - **iOS**: `cd ios && pod install && cd .. && npm run ios`

---

### 3. Monorepo Convenience Scripts (Root)

From the project root `memory/`:

| Command | Action |
| :--- | :--- |
| `npm run dev:server` | Starts Express backend in development watch mode |
| `npm run dev:mobile` | Starts React Native Metro bundler |
| `npm run build:server` | Compiles backend TypeScript to `dist/` |
| `npm run typecheck` | Typechecks both server and mobile workspaces |
| `npm run typecheck:server` | Typechecks only backend code |
| `npm run typecheck:mobile` | Typechecks only mobile application code |

## 🔒 Security & Boundaries

- **Zero Secrets on Mobile**: The mobile app only knows `API_BASE_URL`. Database credentials, storage provider keys, and future AI keys live solely in `server/.env`.
- **User Isolation**: All memory endpoints verify user ID ownership with Better Auth Bearer tokens before accessing database records.
- **External Storage**: Large files and images are uploaded directly to external object storage (S3/Cloudflare R2) via presigned URLs generated by the server.
- **Strict Validation**: All incoming requests are validated with Zod schemas before reaching business logic.
